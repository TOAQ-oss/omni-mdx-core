# `@toaq-oss/mdx-engine`

The React/Next.js visual rendering engine of the TOAQ-oss MDX ecosystem.

[![GitHub](https://img.shields.io/badge/GitHub-TOAQ--oss-181717?logo=github)](https://github.com/toaq-oss)

This package consumes the ultra-fast Abstract Syntax Tree (AST) generated by our Rust core in WebAssembly (`@toaq-oss/core-parser`) and transforms it into interactive, secure, and highly customizable React components.

## ✨ Key Features

* **Security (Error Boundaries):** A faulty component in an MDX file will never crash the entire application. The error is isolated and logged cleanly.

* **Dynamic Props Evaluation:** Complex attributes written as strings (`data={[1, 2, 3]}`) are safely evaluated as real JavaScript objects.

* **Typography & Isolated Components:** The rendering context knows when it is inside a custom JSX component to prevent global Markdown styles from interfering with component design.

* **Native Mathematics:** Seamless integration of `react-katex` for scientific display without additional configuration.

## 🚀 Installation & Build
This package depends on the WebAssembly module generated by the Rust core. To prepare the environment from the root of the monorepo, use our standardized Makefile:

```bash
#1. Install NPM dependencies
npm i @toaq-oss/mdx-engine
```

## 💻 User Guide
Integration into a Next.js application is done in two steps: global configuration and display.

### 1. Configuration (`MdxConfigProvider`)
Wrap your application or page with `MdxConfigProvider` to inject your custom components (such as `<Speaker>` or `<DataChart>`) into the MDX engine.

```tsx
import { MdxConfigProvider } from '@toaq-oss/mdx-engine';
import { Speaker, DataChart, Note } from '@/components/mdx';

const mdxConfig = {
  components: {
    Speaker,
    DataChart,
    Note,
    // You can also redefine standard HTML tags:
    h1: (props) => <h1 className="text-3xl font-bold text-blue-900" {...props} />
  },
  features: {
    math: true // Enabled by default
  }
};

export default function Layout({ children }) {
  return (
    <MdxConfigProvider config={mdxConfig}>
      {children}
    </MdxConfigProvider>
  );
}
```

2. Display (`MDXViewer`)
Retrieve the Markdown text, parse it with the Rust core, and pass the AST to the `MDXViewer`.

```tsx
import { useMemo } from 'react';
import { parse_mdx_to_json, MDXViewer } from '@toaq-engine/mdx-engine';

export default function EpisodePage({ markdownContent }) {
  // Optimized synchronous parsing (zero double rendering)
  const { ast, parseError } = useMemo(() => {
    if (!markdownContent) return { ast: null, parseError: null };
    
    try {
      const jsonAst = parse_mdx_to_json(markdownContent);
      return { ast: JSON.parse(jsonAst), parseError: null };
    } catch (err) {
      return { ast: null, parseError: err instanceof Error ? err.message : String(err) };
    }
  }, [markdownContent]);

  if (parseError) {
    return <div className="error-box">Erreur de syntaxe MDX : {parseError}</div>;
  }

  return (
    <article className="prose lg:prose-xl">
      {ast && <MDXViewer ast={ast} />}
    </article>
  );
}
```

## 🛠️ Included Tools
* `parseProps(propValue: any)`

A robust utility for extracting and parsing data sent from Markdown to your React components. Ideal for processing chart data or complex configurations.

```tsx
import { parseProps } from '@toaq-oss/mdx-engine';

export const DataChart = ({ data }) => {
  // Converts the MDX string “[1, 2, 3]” into a true JS array [1, 2, 3]
  const parsedData = Array.isArray(data) ? data : parseProps(data);
  // ...
};
```
* `<MDXErrorBoundary>`
This component is natively integrated into the `MDXViewer` for each custom component. If a researcher inserts a `<DataChart>` with corrupted data, only that chart will display a red error message, allowing the rest of the script to remain readable and functional.
