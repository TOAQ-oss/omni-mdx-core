# FFI Bindings & Multi-Target Architecture

Omni-MDX is built as a **Universal Rust Core** that exports high-performance bindings to different programming environments. This chapter explores how we bridge the gap between Rust's memory model and the runtimes of Node.js and Python.

## The Bridge Strategy

Instead of maintaining separate parsers, we use **Foreign Function Interfaces (FFI)** to expose the same Rust logic across all targets. 

### 1. Node.js Bindings (`napi-rs`)
For the Node.js ecosystem, we use `napi-rs` to generate native `.node` addons. 
- **Location**: `core-parser/src/ffi.rs`
- **Mechanism**: Rust functions are decorated with `#[napi]`, allowing them to be called directly from JavaScript as asynchronous or synchronous functions.
- **Data Transfer**: We use the **Omni-Core Protocol (OCP)** to send binary buffers instead of heavy JSON strings, significantly reducing the overhead of the JS-Rust bridge.

### 2. Python Bindings (`PyO3`)
The Python integration is handled via `PyO3` and `maturin`.
- **Location**: `core-parser/src/python.rs`
- **Mechanism**: The Rust code defines a Python module (`#[pymodule]`) and classes (`#[pyclass]`) that mirror the internal Rust AST.
- **Feature**: This allows Python users to benefit from Rust's multi-threading capabilities while staying within a familiar Pythonic API.

### 3. WebAssembly (`wasm-bindgen`)
For browsers and Edge runtimes, the core is compiled to WASM.
- **Build Tool**: `wasm-pack`.
- **Use Case**: This acts as a universal fallback when native Node.js addons cannot be loaded (e.g., Vercel Edge Functions or Cloudflare Workers).

---

## Shared Logic Implementation

The `compiler.rs` module acts as the unified entry point for all FFI layers. Whether you call the parser from Python or Node.js, the same execution path is followed:

1. **Input**: Raw UTF-8 String.
2. **Parsing**: The `omni_mdx_core::parse` function is called.
3. **Serialization**: Depending on the target, the AST is either serialized to JSON (standard) or encoded into our custom binary format (high-performance).

---

## Build Automation

To simplify the management of these multiple targets, the root `Makefile` provides dedicated commands:

```bash
# Build for Node.js (Native)
make build-node

# Build for Web (WASM)
make build-web

# Build for Python (Maturin)
make build-python
```

<Note type="info">
This multi-target approach ensures that Omni-MDX remains the fastest parser in any stack, while keeping the maintenance cost low by sharing 95% of the codebase in the Rust core.
</Note>
